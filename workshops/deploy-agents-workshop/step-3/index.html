Step 3 · Remember

6 min

Tell the agent about yourself once, then see it use that in later conversations without asking again.

checkpoint branch step-3-remember

How it works

Sessions hold the events and state of one conversation. Agent Runtime stores them for you (the agent uses VertexAiSessionService). A new session starts empty.

Memory Bank holds facts about a user, scoped by app and user id. After each turn, a plugin sends the turn to Memory Bank, which uses an LLM to extract facts on the topics you allow and merges them with what it already knows. At the start of the next turn, PreloadMemoryTool searches those facts with the new message and adds the matches to the model's instructions.

You choose what is remembered. infra/memory/memory-bank.json limits extraction to two topics, team_and_office and work_preferences, plus explicit instructions. Step 2's grant_agent_access.sh applied it.

Run

Monday (session A). Each agents-cli run starts a new session.

agents-cli run --url "$AGENT_URL" --mode adk \
  "Hi! I'm on the platform team in the Istanbul office, and I prefer to take Fridays off."

Memory Bank extracts facts in the background, usually within one to two minutes. Look at what it stored:

uv run python scripts/memory_bank.py list

Wednesday and Friday (new sessions, no context repeated):

agents-cli run --url "$AGENT_URL" --mode adk "How many leave days do I have?"
agents-cli run --url "$AGENT_URL" --mode adk "Book next Friday off."

Optional: in the console, open Deployments → workplace-assistant → Sessions and Memories to see both stores.

What you should see

$ uv run python scripts/memory_bank.py list - I work on the platform team in the Istanbul office. [team_and_office] - I prefer to take Fridays off. [work_preferences] [leave_agent]: I have submitted your leave request for Friday, 30 October 2026 (1 day). It is pending approval by your team lead, Ayşe Demir (LV-1103). Reminder for Platform team members: if you are on call that day, arrange a swap before your team lead approves it [01-leave-policy.md#platform-team-on-call].

The on-call reminder is the memory at work: nothing in the Friday session said you are on the platform team.

Check

./scripts/check.sh 3
- I work on the platform team in the Istanbul office. [team_and_office] ✔ remembers the team ✔ remembers the office ==> Step 3 checks passed.
If this fails
No memories yet for user 'cli-user'
Extraction is asynchronous. Wait a minute and list again. If nothing appears after three minutes, send the Monday message again.
Memories exist but the agent doesn't use them
Recall happens at the start of a turn and matches on the message. Ask something related (“book leave”, “my office”).
Different user
Memories are per user id. agents-cli run always uses cli-user; scripts/ask.py --user you@example.com lets you choose, and memory_bank.py list --user must match.
Start over
uv run python scripts/memory_bank.py clear deletes the memories of cli-user.
Taking this to a customer
  • Memories are personal data. Agree on topics (keep them narrow), a retention period (Memory Bank supports TTLs), and how a deletion request under KVKK or GDPR reaches Memory Bank. Deleting an Agent Runtime instance deletes its memories.
  • The user id is the security boundary. Memories are scoped by the user id the caller sends. Make sure only a trusted front end (Gemini Enterprise, or your own authenticated app) can call the agent.
  • Data location: memories are stored in the agent's region; extraction uses a Gemini model whose endpoint you set in the Memory Bank config.
  • Cost: storage is USD 0.30 per GiB-month; extraction and retrieval also use model and embedding tokens. Pennies for this lab.
