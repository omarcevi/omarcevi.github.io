Deploy the agent to Agent Runtime with its own Agent Identity, let that identity call the MCP servers, and chat with it.

checkpoint branch step-2-deploy

How it works

What gets packaged. agents-cli deploy uploads the project (minus whatever .gcloudignore excludes) and its Dockerfile. Agent Runtime builds the image in a Google-managed project, so you won't see it in your Cloud Build history. Values in .env become environment variables of the deployed agent, which is why secrets never go there.

What Agent Runtime gives you. A container that scales to zero (min 0, max 10 instances, 1 vCPU, 4 GiB by default) behind two IAM-protected methods, :query and :streamQuery. Sessions are stored by the platform, traces and logs flow to Cloud Trace and Cloud Logging, and the console has a playground for every deployment.

Agent Identity. With --agent-identity the agent gets its own principal, principal://agents.global.…/reasoningEngines/ID, backed by a SPIFFE certificate. You grant roles to the agent, not to a shared service account; deleting the agent ends its access.

Why the model runs on global. Agent Runtime lives in europe-west1, but Gemini 3.x Flash is served from the global and eu endpoints. With Agent Identity the SDK calls Google APIs on their mTLS hostnames, and the eu endpoint has none, so the agent uses global.

Gemini Enterprise. agents-cli publish gemini registers the deployed agent in a Gemini Enterprise app, where employees chat with it next to their other agents. It needs a Gemini Enterprise app; it is optional for this lab.

Run

Tab 2: deploy (about 5 minutes; read the section above while it runs).

source .workshop.env
agents-cli deploy --project $PROJECT_ID --agent-identity --no-confirm-project

Then give the agent's identity access to the MCP servers, and set the Memory Bank topics used in step 3:

./scripts/grant_agent_access.sh

Chat. IAM grants take a minute or two to apply; if the first answer says the HRIS is unavailable, ask again.

AGENT_URL=$(./scripts/agent_url.sh)
agents-cli run --url "$AGENT_URL" --mode adk "What can you help me with?"
agents-cli run --url "$AGENT_URL" --mode adk "How many unused leave days can I carry over?"
agents-cli run --url "$AGENT_URL" --mode adk "What is the salary band for an L5 in Istanbul?"

Remember that last answer: the agent just read the compensation system. In step 4 a policy stops it without touching the code.

Optional: open the console playground: Agent Platform → Agents → Deployments → workplace-assistant → Playground.

If this fails
confirmation required … --project
Non-interactive deploys need --project (and --no-confirm-project), as in the command above.
Deploy fails on setIamPolicy
With Agent Identity, the first deploy grants the agent six project roles, so you need resourcemanager.projects.setIamPolicy (Owner has it). Without it, deploy with --no-agent-identity and skip step 4's gateway (use the fallback).
“HRIS server is unavailable” right after deploying
The run.invoker grants need a minute or two to apply. Ask again. Cloud Run's log shows The IAM principal lacks run.routes.invoke until then.
The first answer takes a minute
Cold start: the agent and the MCP servers scale to zero. Later answers take 5–20 seconds.
A question seems to hang
Shared model capacity occasionally stalls a call. The agent gives up on a model call after 45 seconds and retries up to three times.
No deployed agent from the scripts
Run the scripts from the repo root, where deployment_metadata.json is written.
Taking this to a customer
  • Agent Identity vs service accounts. One principal per agent makes reviews and revocation simple: ask the security team to grant roles to principal://… members, or to a principalSet://…/attribute.platformContainer/aiplatform/projects/NUMBER for all agents in a project.
  • Who may deploy. The first deploy with Agent Identity edits project IAM. Many customers won't give that to developers: have the platform team pre-grant the roles, or run deploys from CI with a dedicated deployer.
  • Secrets. Everything in .env ships as plain environment variables. Use Secret Manager and agents-cli deploy --secrets ENV=SECRET.
  • Cost: about USD 0.085 per vCPU-hour and 0.009 per GiB-hour, billed by the second while handling requests; idle time between turns is not billed. Raise --min-instances only if cold starts matter.
