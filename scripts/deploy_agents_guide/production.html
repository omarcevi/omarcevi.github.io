Production readiness checklist

What to settle with a customer before their agent goes live. Each item points back to the step where you saw it.

Identity and access

  • Each agent has its own Agent Identity; roles go to its principal://, not to a shared service account (step 2).
  • Deploys run from CI with a dedicated deployer; developers don't hold setIamPolicy on production projects (step 2).
  • Only a trusted, authenticated front end can call query/streamQuery; the user id it sends is the boundary for sessions and memories (steps 2, 3).
  • Tools that act for a person use that person's own token (3-legged OAuth through Auth Manager), and the tool server verifies it (step 4).
  • Secrets live in Secret Manager and reach the agent through --secrets, never through .env (step 2).

Governance

  • Every destination is registered in Agent Registry, with tool annotations reviewed by the tool owner (steps 1, 4).
  • An egress gateway is bound and policies are owned by security: organization guardrails, project rules per agent, explicit deny rules for sensitive systems (step 4).
  • New policies ran in DRY_RUN first and the denial logs were read before enforcing (step 4).
  • Model Armor and, where available, semantic governance policies cover prompt injection and data the model must not request (step 4).
  • Organization policies checked: iam.managed.disableAccessPolicyBindings, iam.allowedPolicyMemberDomains, region restrictions.

Data

  • Region chosen for data at rest; the model endpoint (global, multi-region or regional) agreed with the customer's data protection officer (steps 1, 2).
  • Memory topics are narrow, memories have a TTL, and deletion requests (KVKK, GDPR) reach Memory Bank (step 3).
  • Prompt and answer capture in logs is a conscious choice, with a restricted log bucket and retention (step 5).

Operations

  • Dashboard and alerts on turn latency, tool error rate and blocked calls; refused calls are 200s, so alert on logs-based metrics (step 5).
  • Model calls have timeouts and retries; there is a plan for capacity (Provisioned Throughput) if traffic is high or latency matters.
  • Min instances, max instances and concurrency set from a load test, not defaults.
  • A rollback path: Agent Runtime keeps revisions; know how to redeploy the previous version.

Quality

  • An eval set owned with the business, thresholds agreed per metric, and a gate in CI that blocks deploys (step 6).
  • An Online Monitor with a sampling rate and per-run cap that fit the budget (step 6).
  • Incidents and low monitor scores become eval cases before the fix ships (step 6).
