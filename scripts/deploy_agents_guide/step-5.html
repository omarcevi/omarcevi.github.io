Step 5 · Observe

5 min

Follow one leave request from the concierge to the HRIS in Cloud Trace, and open a dashboard that shows blocked calls.

checkpoint branch step-5-observe

How it works

Traces come for free. agents-cli deploy sets GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true, and ADK exports OpenTelemetry spans to Cloud Trace: invoke_workflow for the turn, invoke_agent per agent, call_llm/generate_content per model call, and execute_tool per tool call. Failed tool calls carry error.type.

Logs need OpenTelemetry on Agent Runtime. Plain print() and Python logging from the running container don't reach Cloud Logging; OpenTelemetry log records do. The agent writes its audit event (workplace.tool_blocked) that way and forwards Python warnings too. Setup also turned on prompt and answer events (EVENT_ONLY), which step 6's Online Monitor reads.

Metrics: Agent Runtime publishes request count and latency; ADK publishes tool and agent durations; two logs-based metrics count blocked calls (from the agent's audit event and from the gateway's own log).

Run

Make one leave request (if you didn't book in step 3), wait a minute for the trace to arrive, then:

agents-cli run --url "$AGENT_URL" --mode adk "Book next Monday off as a half day."
./scripts/observe.sh       # creates the dashboard, prints the newest leave-request trace

Open the links it prints: the trace in Trace Explorer, and the Workplace Assistant (workshop) dashboard. The console also shows traces per session under Deployments → workplace-assistant → Traces.

Read it like a profile: the tool calls take milliseconds, the model calls take seconds. That is where latency and cost go. Dashboard tiles: requests per minute, turn latency p50/p95, tool error rate by tool, blocked calls by reason, gateway denials.

If this fails
No trace matching …
Traces arrive one to two minutes after the turn. Book leave again if the last booking was more than three hours ago.
Dashboard tiles say “No data”
Tiles fill as traffic arrives; logs-based metrics only count entries written after they were created (setup created them early for that reason).
No workplace.tool_blocked entries
They only appear after a refused call (step 4). Ask for a salary band again.
Request latency p95 looks huge
Agent Runtime's request latency includes the whole streamed response. The ADK turn-latency tile is the better signal.
Taking this to a customer
  • Prompts in logs are personal data. EVENT_ONLY writes prompts and answers to Cloud Logging. Agree on retention, who may read the log bucket, and whether to route these events to a separate, restricted bucket.
  • Define SLOs early: turn latency, tool error rate and refusal rate are the three the business notices. Alert on the logs-based metrics, not only on HTTP errors: a refused tool call returns 200.
  • Analytics at scale: the BigQuery Agent Analytics plugin (--bq-analytics in agents-cli) writes one row per agent event for SQL analysis.
  • Cost: trace ingestion is USD 0.20 per million spans after 2.5 million free per month; this lab uses a few thousand. Log volume grows with content capture.
