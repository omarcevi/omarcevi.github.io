Teardown

Delete all resources that the lab created. Then make sure that no resource remains.

./scripts/teardown.sh

The script asks for confirmation one time, then deletes the resources in the order of their dependencies. First, it deletes the Agent Runtime instance (with its sessions and memories) and the project roles of its identity. Next, it deletes the online monitor, the access policy and its policy binding, and the gateway with its authorization policy and extension. Then it deletes the Agent Registry entries, the three Cloud Run services, the image repository and the build sources. Last, it deletes the logs-based metrics and the dashboard. At the end, it lists each type of resource and fails if a resource remains:

==> Checking for leftovers ✔ no Agent Runtime instances ✔ no online monitors ✔ no agent gateways ... ✔ no dashboards ==> Nothing left. APIs stay enabled; they cost nothing while unused.

If a deletion was not complete, run ./scripts/teardown.sh --verify-only again later. The script does not delete the project and does not disable APIs.

If you used a project only for this lab, you can delete the project. This removes all resources at the same time: gcloud projects delete YOUR_PROJECT_ID.

IF YOU DO NOT DELETE ITAll parts of the lab scale to zero, so a forgotten lab costs cents per day. The Agent Runtime instance and the Cloud Run services cost money only when they process requests. In this lab, the gateway has no charge when it is idle. Logs and traces stay in the free tiers. Delete the resources anyway.
