Step 1 · Set up

5 min

Get the repo into Cloud Shell, enable the APIs, and deploy the three MCP tool servers the agent will call.

checkpoint branch step-1-setup

How it works

Tools are services with owners. The HRIS, ticketing and compensation systems are separate MCP servers (FastMCP, streamable HTTP) on Cloud Run. One image serves all three; an environment variable picks which. Each service accepts only callers with roles/run.invoker: there is no public URL.

Read-only tools say so. Every tool carries MCP annotations such as readOnlyHint. Agent Registry stores them with the tool list, and gateway policies can use them later.

The gateway takes time, so it starts now. Creating Agent Gateway and attaching IAP as its authorizer takes about six minutes. setup.sh starts it in the background; you use it in step 4.

Run

Open in Cloud Shell →

The button clones the repo into Cloud Shell and opens a tutorial panel with every step's commands, each with a copy button; keep this guide open for the explanations. In the Open in Cloud Shell dialog, tick Trust repo, then Confirm. Without it Cloud Shell runs in ephemeral mode: your files are deleted when the session ends, and Google's docs say such sessions don't get your credentials. Or open Cloud Shell and clone the repo yourself. Then:

# skip the clone if you used the Open in Cloud Shell button
git clone {{REPO}}.git
cd cloud-agents-workshop

gcloud config set project YOUR_PROJECT_ID
uv tool install --force "google-agents-cli>=1.11"
export PATH="$HOME/.local/bin:$PATH"   # Cloud Shell has an older agents-cli in /usr/local/bin
./scripts/check.sh 0                 # tools, login, billing
./scripts/setup.sh                   # APIs, MCP servers, registry (about 2 min); the gateway keeps building in the background

Check

The 403 without a token is the point: nothing on Cloud Run is open to the internet.

If this fails
agents-cli: command not found, or check.sh 0 reports an agents-cli older than 1.11
Cloud Shell comes with an older agents-cli in /usr/local/bin, which wins until ~/.local/bin is on your PATH. Run the two install lines above again in this terminal; a new Cloud Shell tab needs the export line too.
Billing ✘ in check.sh 0
Link a billing account to the project in the console. No billing account? Pair with a neighbour.
Cloud Build fails with a permission error
New projects take a minute to grant the build service account its roles. Wait a minute and run ./scripts/setup.sh again; it skips what already exists. In an organization that turns off default grants, give the Compute Engine default service account roles/cloudbuild.builds.builder.
FAILED_PRECONDITION or SERVICE_DISABLED right after enabling APIs
API enablement takes a moment to spread. Run ./scripts/setup.sh again.
.setup-gateway.log ends with GATEWAY FAILED
Read the error above it. Agent Gateway may not be available to your project yet; you can still do steps 2, 3, 5 and 6, and use ./scripts/fallback_step4.sh in step 4.
Taking this to a customer
  • Ask the platform team first: which region (data residency), which project the agents live in, and which organization policies apply. Two that block this lab: iam.allowedPolicyMemberDomains can reject principal:// members, and iam.managed.disableAccessPolicyBindings (on by default in new organizations) blocks the gateway's access policy.
  • Tools have owners. The HRIS team owns the HRIS MCP server, its IAM and its tool annotations. Agree on who registers servers in Agent Registry and who may grant run.invoker.
  • Cost: Cloud Run with min instances 0 costs nothing while idle; one image build is a few cents of Cloud Build time.
